## 英文股东表解析器（提交 af6623b）——用户提问「港股是否也需要英文/繁体解析器」

**实测结论（纠正了假设）**：
- 披露易同时提供繁体中文版（2025 年報）与英文版（ANNUAL REPORT 2025）
- **中文版用 pypdf 提取是 CID 乱码**：简体与繁体关键词命中**均为 0**（'ʮ̡'、'ੂБ' 之类）
- 英文版提取完全正常：VIE 56 页、WFOE 4 页、corporate structure p.73、Contractual Arrangements p.78/192、
  **substantial shareholders p.79**（"INTERESTS OF SUBSTANTIAL SHAREHOLDERS … Part XV of the SFO"）
- 所以：**英文解析器是港股+美股共同主路径**（不是美股补丁）；**繁体解析器当前做不了**
  （没有可用输入），真要做需先换 pdfplumber/PyMuPDF 修中文提取 + 简繁归一化

**实现**：`verify/shareholders.py` 加 `extract_holders`（中英双通道）+ `extract_en_holders`
- 表格行：名称 + capacity 描述 + 股份数 + 百分比；叙述式：beneficially owns …
- `_soft_unwrap` 合并 PDF 软换行（"Advance Data Services \n Limited"）
- capacity 截断词表：Long/Short position、Corporate (Note N)、Beneficial owner、Investment manager…
- 英文虚词表：own/owns/held/represents/approximately…

**三个坑**：
1. capacity 含数字（"Note 1"）→ `[^0-9%\n]` 阻断匹配，必须改为 `[^%\n]`
2. group1 非贪婪会把 "MIH Internet Holdings B.V." 截成 "MIH" → 改贪婪，由 capacity 截断得全称
3. ruff 会重排 import（`extract_from_hits`→`extract_holders` 替换失效 → NameError）
   并把 `"""...""".split()` 改写成字面列表（后续字符串替换失效）——批量改完必须再校验

**实测**：腾讯真实英文年报 p.79 抽出 MIH Internet Holdings B.V 22.80%、Advance Data Services Limited 8.82%；
港股 00700 真实跑通（9 节点/4 VIE 边/UBO 马化腾 54.29%/置信度 96）；BABA 交叉验证 1→7 条。51 测试全绿。

## 20-F Item 7 股东表 HTML 结构化解析（提交 e47aa8c）

**关键认知**：20-F 是 **HTML 不是 PDF**，Item 7 持股表就是标准 `<table>`
（`['Name','','Beneficial ownership (Shares)','','Percent']`）→ 直接解析行列远比文本正则可靠。

- 新模块 `overseas/htmltable.py`（零依赖，标准库 html.parser）
  - **栈式解析**：单层状态会被内层 `</table>` 顶掉导致后续表格错位（嵌套用例已覆盖）
  - is_holder_table：表头须同时含 Name + 持股语义 + %
  - holders_from_table：不依赖列序——首个非空单元格为名称、含 % 的单元格为比例；
    跳过表头/分组行（":" 结尾）/合计行（"as a group"）/0.0% 记录
- crosscheck 双通道：HTML 表格优先；**HTML 有结果时文本通道退化为仅叙述式**（否则同一份 HTML 被二次解析产生
  "Eddie Yongming WU 19,706,418" 这类噪声）

### 顺带修出的 3 个真 bug
1. **运营实体节点分裂**：VIE party_b 无信用代码建「名称@CN」节点，工商穿透又建「信用代码」节点 → UBO 丢失。

- Pydantic 反序列化后的 StrEnum 用 `str()` 会带类名前缀，做字典键一律取 `.value`
